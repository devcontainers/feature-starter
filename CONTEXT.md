# Dev Container Features — Domain Glossary

## Concepts

### Feature
A sharable, composable unit of container configuration. Consists of:
- `devcontainer-feature.json` — metadata, options, dependencies
- `install.sh` — root-executed entrypoint script
- Options are passed as **capitalized, sanitized** environment variables

### Option
A user-configurable parameter declared in `devcontainer-feature.json`. Resolved at build time and injected as env vars into `install.sh`.

### Scenario
A named test configuration for a feature. Lives in `test/<feature>/scenarios.json`. Each scenario has its own test script.

### Autogenerated Test
Default test run against a feature with no options specified. Uses `test/<feature>/test.sh`.

### Global Scenario
Multi-feature integration test. Lives in `test/_global/scenarios.json`.

## Feature Lifecycle

1. **Declare** — write `devcontainer-feature.json` with options and `installsAfter`
2. **Implement** — write `install.sh` to perform installation as root
3. **Test** — autogenerated + scenario + global tests
4. **Validate** — `devcontainer features validate --base-path ./src`

## Boundaries

- Features run as **root** during container build
- Must respect `_REMOTE_USER` and `_CONTAINER_USER` for user-scoped operations
- Must not hardcode user home directories — use `_REMOTE_USER_HOME`

## Built Features

### `sandcastle`
Orchestrates AI coding agents in isolated sandboxes. Installs `@ai-hero/sandcastle` via npm.
- **Fail-fast**: checks for Docker/Podman/Vercel CLI before proceeding
- **Secrets**: does not inject tokens; documents need for `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`
- **Options**: `version`, `providerCheck`

### `claude-code-ollama`
Configures Claude Code to route model requests to an Ollama backend.
- **Scope**: model-related env vars only (`ANTHROPIC_BASE_URL`, model defaults, auth token, log level)
- **Assumption**: Ollama is already running externally or installed separately
- **Options**: `baseUrl`, `authToken`, `haikuModel`, `opusModel`, `sonnetModel`, `subagentModel`, `logLevel`
- **Implementation**: merges env vars into `~/.claude/settings.json` using Python `json` module

### `claude-code-privacy`
Configures Claude Code with privacy-hardened defaults.
- **Scope**: telemetry, reporting, updates, nonessential traffic, prompt caching, feedback
- **Options**: `disableTelemetry`, `disableErrorReporting`, `disableFeedbackCommand`, `disableUpdates`, `disableNonessentialTraffic`, `disableFeedbackSurvey`, `skipPromptHistory`, `cleanupPeriodDays`
- **Implementation**: merges env vars and top-level `cleanupPeriodDays` into `~/.claude/settings.json` using Python `json` module

### `claude-code-hooks`
Installs bash hooks for Claude Code lifecycle telemetry, state tracking, and policy enforcement from a Git repository.
- **Scope**: clones hook scripts into `~/.claude/hooks/` and merges wiring templates into `~/.claude/settings.json`
- **Options**: `repository`, `branch`, `installStatusLine`
- **Implementation**: clones repo to temp directory, copies `agent/`, `session/`, `turn/`, `lib/`, `config/` to hooks directory, then merges JSON config using Python. Fixes ownership with `chown`.

## Design Decisions

### JSON manipulation in shell
Both `claude-code-*` features use `python3` for reliable JSON read/write. This is more robust than `jq` (not guaranteed) or `node` (may not be present). The base images used in CI (debian, ubuntu, devcontainers/base) all include python3.

### User-scoped file writes
Install scripts run as root but need to write to `~/.claude/settings.json`. We use `_REMOTE_USER_HOME` (provided by the devcontainer CLI) and `chown` the resulting directory to `_REMOTE_USER`.

### Feature separation
Privacy settings were intentionally split from Ollama backend settings because:
- Privacy is useful regardless of backend (Anthropic API or Ollama)
- Ollama configuration is about model routing, not data collection
- Users may want one without the other
